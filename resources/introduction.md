# Battle City 0.4.0 设计与实现

0.4.0 是坦克大战复刻版的重写版：TypeScript + React 19 + PixiJS v8 + zustand，vite 构建。本文介绍游戏规则、数值、AI 和整体结构，数值都按当前代码核对过。

- 0.3.0（React + SVG + redux-saga）的开发过程见 [journal.md](./journal.md)。
- NES 原版数值与出生 / AI 规则的逐条调研见 [nes-values/](./nes-values/README.md)，其中 README 有与当前实现的差异表。

## 一、整体结构

| 目录                     | 职责                                                     |
| ------------------------ | -------------------------------------------------------- |
| `src/engine`             | 纯逻辑，无 DOM：对局、实体、碰撞、AI                     |
| `src/render`             | PixiJS 绘制战场，画面固定放大 2 倍                       |
| `src/ui`                 | React + SVG 像素界面：标题页、选关、编辑器、画廊、结算等 |
| `src/input`、`src/audio` | 键盘输入、音效（`src/audio/sounds/*.ogg`）               |
| `src/lan`                | 局域网联机                                               |
| `src/stages`             | 35 个内置关卡                                            |
| `bin/`                   | npm 包的 CLI（本地 web server、联机主机）                |

- **定步循环**：`Game.ts` 用 accumulator 按 `STEP_MS = 1000/60` 推进逻辑，单帧最多补 250ms。渲染只读引擎状态。
- **可复现**：引擎里所有随机（bot 决策、开火判断、道具种类和位置）都读 `SessionOptions.random`。游戏传 `Math.random`，测试传 `seededRandom(seed)`，同一种子整局一致。
- **对局阶段**（`GameSession`）：`enter`（入场幕布 100 帧）→ `playing` →（胜利 4000ms / 全灭 3000ms 后）`statistics`（结算）→ 胜利进下一关，最后一关直接 `ended`；全灭进 `gameover`。老鹰被毁跳过结算直接进 `gameover`：GAME OVER 字样上升 2000ms 后再停 3000ms（战场照常运行），然后 `ended`。

## 二、坐标与尺寸

- 1 block = 16px，战场 13×13 block（208px）；屏幕含右侧 HUD 共 16×15 block。
- 坦克 16×16，子弹 3×3，位置都是左上角坐标。
- 地形子格边长：砖 4px、钢 8px，河、雪、森林 16px。
- 坦克垂直转向时，坐标吸附到最近的、能通行的 8px 倍数（`movement.ts`）。
- AI 寻路用 26×26 的 spot 图，每格 8px，坦克中心落在 spot 上（`ai/spots.ts`）。

## 三、路由

hash 路由，双人模式在地址后加 `?multi-players`（在选关、对局、结束页之间透传）。

| 地址                                        | 页面                                  |
| ------------------------------------------- | ------------------------------------- |
| `#/`                                        | 标题页（未匹配的地址也显示标题页）    |
| `#/choose/:stage`                           | 选关                                  |
| `#/stage/:stage`                            | 对局                                  |
| `#/gameover`                                | 结束页                                |
| `#/list/:tab/:page`                         | 关卡列表，tab 为 `default` / `custom` |
| `#/editor/:view`                            | 关卡编辑器，view 为 `config` / `map`  |
| `#/gallery/:tab`                            | 画廊                                  |
| `#/options`                                 | 键位与托管开关                        |
| `#/lobby`、`#/lobby/create`、`#/lobby/room` | 联机大厅、创建房间、房间页            |

`:stage` 是关卡名。省略或无效的参数会被 replace 成默认值：选关、对局回到第一关，列表 `/list/default/1`，编辑器 `/editor/config`，画廊 `/gallery/tanks`（tab 还有 texts / fire / misc / title-scene / statistics / gameover / info）；没有本局结果时 `#/gameover` 回到标题页，不在房间时 `#/lobby/room` 回到大厅。

## 四、对局规则

### 坦克数值

数值在 `src/engine/values.ts`。玩家吃 star 按 basic → fast → power → armor 升级。

|            | 移速 px/ms | 弹速 px/ms | 开火间隔 | 同时子弹 | 子弹威力    | HP  |
| ---------- | ---------- | ---------- | -------- | -------- | ----------- | --- |
| 玩家 basic | 0.045      | 0.12       | 300ms    | 1        | 1           | 1   |
| 玩家 fast  | 0.045      | 0.18       | 200ms    | 1        | 1           | 1   |
| 玩家 power | 0.045      | 0.18       | 200ms    | 2        | 1           | 1   |
| 玩家 armor | 0.045      | 0.18       | 200ms    | 2        | 3（可破钢） | 1   |
| bot basic  | 0.03       | 0.12       | 300ms    | 1        | 1           | 1   |
| bot fast   | 0.06       | 0.18       | 200ms    | 1        | 1           | 1   |
| bot power  | 0.03       | 0.24       | 200ms    | 1        | 2           | 1   |
| bot armor  | 0.03       | 0.18       | 200ms    | 1        | 1           | 4   |

- 玩家子弹每次命中 bot 固定减 1 HP，不看星级，armor 始终要打 4 下。
- 得分：击毁 basic / fast / power / armor 得 100 / 200 / 300 / 400，吃道具 500，armor 吃 star 额外再加 5000。射手阵亡后，他留在场上的子弹击毁 bot 不计分也不计击杀。
- 初始 3 条命，每累计 10000 分加 1 条。双人时没命的玩家可以按开火借队友的命。

### bot 出生

规则按 NES 原版，常量在 `constants.ts`。

| 项       | 规则                                                             |
| -------- | ---------------------------------------------------------------- |
| 同屏上限 | 单人 4 辆、双人 6 辆，出生闪烁中、爆炸和得分弹出播完前的也占名额 |
| 出生点   | 中 → 右 → 左 轮流，不检查占用                                    |
| 出生间隔 | 190 − 4×关卡号 帧，双人再减 20，35 关封顶；开局第一辆立即出生    |
| 出生闪烁 | 56 帧                                                            |
| 带道具   | 每关第 4、11、18 辆                                              |

### 道具

- **掉落**：带道具的 bot 第一次被击中（不必击毁）就掉落一个道具。带道具的 bot 出场时清掉场上已有的道具；道具不会因为长时间没人拾取而消失。
- **位置**：在 8px 网格上随机选，要求道具中心 8×8 的四个象限里有 1–3 个碰到砖、钢、河或老鹰。
- **种类**：老鹰外露时 50% 给 shovel；否则有玩家还是 basic 时 40% 给 star；否则六种等概率。

| 道具    | 效果                                                                            |
| ------- | ------------------------------------------------------------------------------- |
| tank    | 加 1 条命                                                                       |
| star    | 升一级；已是 armor 时加 5000 分                                                 |
| grenade | 炸掉场上所有 bot，计入击杀数但不加分                                            |
| timer   | 冻结 bot：计数 10，每 64 帧边界减 1（约 576–640 帧），期间 bot 不决策，出生照常 |
| helmet  | 无敌 630 帧（复活自带 135 帧）                                                  |
| shovel  | 老鹰外墙变钢 1076 帧，之后闪烁 6 次（每 16 帧）变回砖                           |

### 队友误伤

玩家子弹打中队友时，队友定身 1000ms，期间可以转向不能前进。队友戴着头盔时子弹直接消失，不定身，和 NES 一致。

### 冰面滑行

只有玩家坦克会滑，bot 不滑（NES 也是这样）。实现在 `movement.ts` 的 `applyPlayerMove`，托管的坦克同样受影响。

- 判定：坦克中心所在的格子是雪地。
- 在冰上剩余滑行量为 0 时按方向键（包括按着方向键开上冰面），剩余滑行量设为 16px；剩余量大于 8px 时锁定，方向键无效、沿朝向继续走；之后松手会滑完剩余量。NES 是 28px、剩余 ≥ 16 时锁定，试玩觉得太滑，减到约一个坦克长。
- 被挡住时滑行量照样消耗；定身时的按键也按松手处理；冲出冰面立即恢复操控，剩余量保留到下次上冰。
- 起滑音效 `snow_slide` 按原版 ROM 的音效数据（Pulse 1 四个上行音，约 70ms）合成。

## 五、bot AI

四种 bot 共用一套 `BotBrain`（`ai/bot-brain.ts`），移植自 0.3.0 的 saga 实现，只在数值上有区别。它是一个帧循环状态机：规划 → 沿路径走 →（进攻时转向、开火）→ 重新规划；找不到路时等 200ms 再规划。

- **游荡还是进攻**：每次规划掷一次，去打老鹰的概率在本关前 60s 从 0 线性升到 20%。开局多游荡、越往后越凶。老鹰已毁时只游荡。
- **游荡**：随机选一个可通行的 spot，BFS 寻路走过去。
- **进攻老鹰**：以老鹰周围 8 格为弱点，沿四个方向累计打过去要穿几层砖、钢（`fire-estimate.ts`），在不用穿钢、砖不超过 8 层的射击位里随机选一个走过去，转向老鹰连开 1–2 发（砖 ≤3 层 1 发，更多 2 发）。
- **打砖开路**：只在进攻时用。同时算现成路和打砖路线（一层砖折算多走 6 格），打砖路线更短或现成路走不通时才打砖。代价定得高，是为了只在出生区被砖隔开、或者打砖能省一大截时才打，免得 bot 太强。
- **受阻**：连续 200ms 没位移（冻结除外）就重新规划。
- **打到老鹰外墙之后**：子弹打掉老鹰外墙的砖或打中老鹰的那辆 bot，3s 内不朝老鹰开火（前方先挡着玩家或钢的照开），也不去进攻；每辆 bot 各自计时。免得第一发开出缺口、紧接着一发就打掉老鹰。

开火（移动中每隔一个开火间隔判断一次，用同一个随机数 r 比较，满足任一条就开）：

| 条件                   | 开火概率                   |
| ---------------------- | -------------------------- |
| 朝向前方最近的障碍是砖 | 0.6 − 距离/300             |
| 老鹰在朝向上           | 前方 96px 内 0.6，身后 0.1 |
| 最近的玩家在朝向上     | 前方 96px 内 0.5，身后 0.1 |
| 兜底                   | 0.05                       |

- **转身打侧面**：沿路径走时，侧面或背后 96px 内、中间没有砖钢的玩家，每次开火判断时按概率转过去停 300ms 开火。概率在本关前 60s 从 0 升到 5%，免得站在 bot 侧面绝对安全。
- bot 不躲子弹。

## 六、玩家托管

玩家一段时间不操作，就由 AI（`TeammateBrain`）驾驶他的坦克。单人时游戏可以当演示看，AI 对 AI 也能一直打下去。

- **触发**：每关坦克出生完成后，一直没按键满 2s，或按过键之后连续空闲满 5s（`AUTOPILOT_START` / `AUTOPILOT_IDLE`）。阵亡等待复活时空闲计时暂停、不清零。
- **交还**：按下该玩家的任一绑定键立即交还，这次按键在同一个 tick 生效。结算页、入场幕布里的按键也算交还。
- **跨关**：谁在驾驶跨关保留；上一关结束时是托管的，下一关出生后直接由 AI 驾驶。
- **开关**：Options 页的 autopilot，默认开。
- **标注**：托管期间 HUD 的 Ⅰp 换成红色 cpu；结算页、结束页按胜负确定那一刻的状态标 CPU。托管打出的分数照常计入最高分。
- AI 不会自动借命。

### TeammateBrain

每 300ms 规划一次（受阻、自保动作结束后立即规划），在下列候选里取代价最小的。代价以 8px 格为单位。「单人」「双人」按场上的玩家坦克数算，双人局里队友阵亡或还没出生时按单人处理。

| 候选                                            | 代价                                                   |
| ----------------------------------------------- | ------------------------------------------------------ |
| 射击位：与某辆 bot 同行或同列、朝它开火先打到它 | 路程 + 穿砖层数×2，站到队友半场 +5，威胁老鹰的 bot −40 |
| 道具                                            | 路程 − 60（有真人在场时 − 10，留给真人）               |
| 开路防守：老鹰四周值得打通的路线（单人）        | 到路线起点的路程 − 30                                  |

以上一个都没有时才回去守家：单人守老鹰正上方，双人左右各守一侧，代价为路程 + 偏离守家位每 8px 加 4。

- 威胁老鹰的 bot：4000ms 内能走到打得到老鹰的位置（最多穿 3 层砖、横向偏差不超过 9px，`eagle-threat.ts`）。
- 双人都在场时，P1 管左半场、P2 管右半场；两人都托管时只有离道具近的去拿。
- 寻路时 bot 炮口前 96px 的格子按 bot 剩余 HP 加代价；受阻时挡路的格子 2000ms 内不走；1500ms 没挪动就把目标附近禁用 5000ms。

移动时按优先级取第一个成立的（自保逻辑在 `self-defense.ts`，每条都用 arena 对照过）：

1. 对射抵消：600ms 内会被 bot 子弹打中（中间没有砖钢挡着）、炮口能对上来弹、自己又能马上开火时，转过去开火抵消。
2. 站位调整：多血 bot 在 48px 内正对自己时横移出射线；bot 在 96px 内正对但炮口错开时横移对齐。
3. 沿路径走：前方是能打掉的砖就停下打；会撞上横穿的子弹就等它过去；下一步会进入 48px 内能立即开火的 bot 的射线就先等（最多 1000ms，老鹰受威胁时不等）；它的子弹还在飞时横穿是安全的。
4. 戴头盔时不做 1、2。

开火：打砖或对射时一直按；否则只在朝向上先碰到 bot、且中间没砖或 bot 在 96px 内时开火，先碰到队友或老鹰时不开。

强度只靠 arena 衡量，单人通关率约 34%，双人约 77%（35 关 × 12 种子，全程 AI 对 AI）。

## 七、AI 共用的基础设施

- **意图接口**（`ai/controller.ts`）：键盘、`BotBrain`、`TeammateBrain` 都实现 `TankController { move, fire }`，只输出意图，不改坦克状态。`BattleScene` 对所有坦克执行同一段：move → 移动（玩家多一层冰面滑行）→ fire。
- **AIContext**：每个 tick 组装一次，所有 AI 共用：碰撞世界、地形、坦克、子弹、道具、spot 图、随机源、本关时间、关卡号、各玩家的坦克和驾驶者。
- **寻路**：BFS（`pathfinding.ts`）给 bot 走现成路；打砖 Dijkstra（`dig-path.ts`）每层砖加一个代价（默认 2，bot 用 6），打不掉的砖（老鹰外墙、子弹打不中的偏边残砖）视为不通。
- **PathFollower**：把同方向的连续 spot 合成一段，先转向再前进，正好停在目标上；冲过目标（冰面）也算到达。
- **子弹通道**（`lane.ts`）：扫描从某位置朝某方向开火会依次碰到什么，砖按 4px 一层计。自保的射线判断和「该不该停下打砖」都基于它。

## 八、局域网联机

`battle-city host` 在局域网上起 web server 和联机中继（`bin/lan-relay.js`，`/lan` websocket），打印可分享的大厅地址。开发时用 `pnpm dev --host`。

- **主机权威**：房主的浏览器运行引擎；加入者每个 tick 把输入编码成整数发给房主，房主把它当作 2P 的按键。
- 房主每一帧画面只要逻辑推进过，就把画面编码后广播，加入者用同一套渲染器画出来。引擎本身不感知联机。
- 中继开启 permessage-deflate，相邻帧重复内容多，一局下行约 2KB/s。
- 大厅流程：房间列表 → 创建房间（选关）→ 房间等待页 → 开局。
- 暂停：任意一方按 Esc 双方一起停，只有暂停的一方能恢复；暂停方的菜单里还能离开房间。由房主判定（`lan/pause.ts`）。
- 任意一方的标签页切到后台时自动按该方暂停（后台 rAF 停了，房主的引擎和客机的输入都会断）。
- 联机分数按本地双人规则刷新两边各自的最高分。
- 限制：只支持内置关卡，没有断线重连，不启用托管。

## 九、测试

`pnpm test` 跑单测，覆盖引擎规则、AI、托管、联机等。其中 `test/trace.test.ts` 录了固定种子下的坦克与子弹轨迹，是 bot AI 与引擎的回归基线（录制时关闭托管），快照变了要先查原因。

`pnpm arena` 让全部关卡 AI 对 AI 无头打完，统计通关、老鹰被毁、全灭、超时的局数，用来衡量 AI 改动；结果对种子敏感，结论要换一组种子（`ARENA_SEEDS`）复核。
