# NES Battle City：bot 出生规则与 AI

## 约定

- 1 帧 = 1000/60 ms；1 block = 16px。
- 地址均指 [D] `bank_FF.asm` 中的 ROM 地址。
- 可信度：高 = 反汇编逐条指令核对；中 = 单一逆向来源或只核对了部分指令。
- 「我们当前」按提交 6dd7c5e 核对。

## 1. 出生调度（`$DB48`）

- 计时器 `$82` 非 0 时每帧减 1；为 0 时，若还有待出场的 bot 且有空槽位，就重新装入 S 并出生一辆。
- 场上满员时计时器停在 0，不会重新倒数；一有空位，下一帧就出生。只有真正出生时才重置计时。
- 每帧最多出生 1 辆。
- 正在播出生动画和正在爆炸的坦克都占着槽位，要等爆炸结束（`$DE07`）才释放。
- S 小于出生动画时长（约 56 帧）时，会有多个出生动画同时进行：1P 从第 34 关起，2P 从第 29 关起。
- 冻结不影响出生：`$DB48` 不检查冻结，计时器照常倒数；新出生的 bot 激活后才被冻住。

## 2. 出生点与出生动画

- 出生点序号先加 1 再取用，每关开始时清零，所以顺序是 中 → 右 → 左 → 中…
- 出生时不检查出生点是否被占，与已有坦克重叠也照样出生。
- 出生时会把出生点那 16×16 的地形清成空地（`$E3B2 LDA #$0F; JSR $D80B`），玩家出生也一样。我们没有实现这一点，自定义关卡在出生点放砖块时行为会不同。
- 出生动画期间：子弹打不着（`$E786` / `$E788` 跳过这类坦克）、不会开火、不挡路。
- 出生动画的时长与关卡、难度无关。

## 3. 冻结（timer 道具）

- 拾取时计数设为 10（`$E9F5`），只在全局帧计数满足 `$0B & $3F == 0` 的那一帧减 1（`$DC00`），因此实际冻结 576–639 帧，随全局帧计数的相位浮动。
- 冻结期间 bot 不移动、不决策、不开火（`$DC1D`–`$DC23` 只冻结活动状态）。
- 暂停时不跑游戏逻辑，会错过减 1 的时机，实际冻结时间被拉长。

## 4. 移动决策（`$DE72`）

- 行驶时直行；坐标 x、y 都是 8 的倍数时，以 1/16 概率重新决策，平均约每 8 格决策一次。
- 撞墙时：75% 原地停 2 个 tick 后继续撞；25% 掉头，若正好在格点上，改为下一 tick 50% 重新决策、50% 在掉头方向上左转或右转 90°。
- 决策按本关已过时间分三个阶段。设 k = ⌊本关帧数 / 64⌋：
  - k > ⌊S / 4⌋：朝老鹰（120, 216）走。
  - k > ⌊S / 8⌋：朝玩家走。1P 追 P1；2P 时偶数槽位追 P1、奇数槽位追 P2，目标阵亡就换另一个。
  - 否则：4 个方向随机选一个（可能选到原方向）。
- 朝目标走时只看 dx、dy 的正负号：50% 竖向优先、50% 横向优先，定一次方向后直行，不持续修正（`$DDA2` + 查表 `$E486`）。
- k 是 8 位计数器，约 273 秒后回绕，bot 会退回随机阶段。这是原版 bug，不复刻。

## 5. 开火（`$E162`）

- 每帧对每辆 bot 掷一次 1/32，前提是它自己没有子弹在场（每辆 bot 最多 1 发）。
- 子弹沿车头方向发射，不瞄准，也没有专门打砖的逻辑；打砖开路是撞墙与随机开火的副作用。
- 四种 bot 的 AI 完全相同，只在速度、弹速和耐打上有区别。

我们让打掉老鹰外墙的砖或打中老鹰的那辆 bot 3s 内不朝老鹰开火、不去进攻（`BotBrain.onBaseHit`），有意保留：不然第一发开出缺口、紧接着一发就打掉老鹰，托管对局里老鹰被毁比全灭还多。

## 6. 坦克之间的阻挡（`$E181`）

- 移动前给每辆活动坦克所在的地图格打上占位标记（`$E1F3`），移动探测把带标记的格子当成墙，移动后再清除（`$E1FA`）。所以坦克会互相阻挡，但占位并不是完整的 16×16。
- 出生动画中和爆炸中的坦克不打标记（`$E189` / `$E18B`），别的坦克可以开进出生点。我们让出生闪烁区域挡路（`BattleScene` 的 `restrictedAreas`），有意保留，避免坦克和刚出生的坦克叠在一起。
- 可信度中高：两辆坦克重叠后具体怎么移动没有验证。vgrichina 的笔记称「坦克之间没有碰撞」，与反汇编不符；megabars 的 `$E181` 只实现了冰面标志，没有实现占位标记（gameplay.ts:1047）。
